# Как описывается проверка

Файл `config/status.json` читают оба наблюдателя — агент на сервере и внешний
сторож. Правила оценки у них одинаковые, поэтому и описание проверок одно.

Порядок проектов в файле — это порядок на странице и в боте.

## Поля проверки

| поле           | зачем                                                                          |
| -------------- | ------------------------------------------------------------------------------ |
| `id`           | ключ, к которому привязана вся накопленная история. Переименование обнуляет её |
| `name`         | как называется в интерфейсе                                                    |
| `note`         | пояснение для оператора                                                        |
| `impact`       | что падение значит для пользователя. Показывается первой строкой в блоке сбоев |
| `url`          | адрес одиночной проверки                                                       |
| `expect`       | ожидаемый код ответа, по умолчанию `200`                                       |
| `critical`     | падение роняет вердикт проекта. По умолчанию `true`                            |
| `slowMs`       | выше порога ответ считается медленным, а не сломанным. `0` — без порога        |
| `bodyIncludes` | подстрока, которая обязана быть в теле                                         |
| `expectType`   | подстрока, которая обязана быть в `Content-Type`                               |
| `allowHosts`   | куда, кроме исходного хоста, разрешено уводить редиректом                      |
| `cert`         | имя хоста, у которого проверять TLS-сертификат                                 |
| `steps`        | сценарий из нескольких запросов вместо одиночного GET                          |

## Почему `critical` по умолчанию `true`

Быть второстепенной проверкой — это решение, а не следствие забытой строки.
У обычного `bool` «не задано» неотличимо от «неважная», поэтому в агенте поле
описано указателем: пустое значит критичная.

Что считать второстепенным — вопрос продуктовый, а не технический. Сейчас
таких две:

- **API админки ChillHub** — публикация сборок. Пользователей не затрагивает:
  уже выложенное раздаётся как обычно.
- **Service worker MetroKit** — офлайн-режим. Сайт без него работает, ломается
  только обновление офлайн-копии у новых посетителей. Для PWA решение спорное
  и меняется одним булевым полем.

## Пороги `slowMs`

Выставлены с запасом (1.5–4 с) и по-хорошему требуют подстройки по
накопленной статистике: занижение даст ложное «медленно», завышение —
пропущенную деградацию.

## Сценарии

Одиночный GET проверяет, что эндпоинт отвечает; сценарий — что пользовательский
путь проходим целиком.

```json
"steps": [
  {
    "name": "последняя версия",
    "url": "https://launcher.samoy.love/manifests/launcher/latest.json",
    "capture": { "version": "version" }
  },
  {
    "name": "манифест сборки",
    "url": "https://launcher.samoy.love/manifests/launcher/{version}.json",
    "bodyIncludes": "\"files\""
  }
]
```

`capture` кладёт поле JSON-ответа в переменную, следующий шаг подставляет её
в URL по имени в фигурных скобках. Если шаг падает, в причине названо, какой
именно: «шаг «манифест сборки»: HTTP 404».

Эта проверка ловит публикацию, доехавшую наполовину: версия объявлена, а
забрать её нечем. Одиночный GET по `latest.json` такого не видит — он
отвечает 200.

## Что проверяется у каждого сервиса сейчас

| проверка                   | критичн. |   порог | тело / тип              |
| -------------------------- | :------: | ------: | ----------------------- |
| ChillHub · Сайт            |    да    | 3000 мс | `</html>` + `text/html` |
| ChillHub · API манифестов  |    да    | 2000 мс | `"version"` + `json`    |
| ChillHub · Путь обновления |    да    | 4000 мс | сценарий из двух шагов  |
| ChillHub · API админки     |   нет    | 2000 мс | `ok`                    |
| Snakes · Игровой сервер    |    да    | 1500 мс | `ok`                    |
| Snakes · Клиент            |    да    | 3000 мс | `</html>` + `text/html` |
| MetroKit · Сайт            |    да    | 3000 мс | `</html>` + `text/html` |
| MetroKit · Service worker  |   нет    | 2000 мс | `javascript`            |
| samoy.love · Сайт          |    да    | 3000 мс | `</html>` + `text/html` |

Маркеры выбраны по живым ответам, а не наугад. `</html>` ловит обрыв ответа:
усечённая страница закрывающего тега не содержит. `expectType: javascript` у
service worker ловит главный тихий сбой этой проверки — SPA-фолбэк отдаёт HTML
вместо скрипта, и код при этом 200.
